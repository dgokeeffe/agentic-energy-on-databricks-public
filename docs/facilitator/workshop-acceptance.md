# Workshop acceptance

A participant change is accepted only when one selected `workshop-ready` GitHub
issue completes the shared sequence below.

- The issue and governed implementation were inspected.
- Requirements name measurable operator results, source, grain, units,
  freshness, corrections, intervention, identity, and prepared/live status.
- The plan names exact files, deterministic tests, eval criteria, review, and
  stops, and a person who did not draft it approves it.
- Implementation stays within the approved files and preserves NEM semantics.
- Focused and complete applicable tests, Markdown links, repository safety, and
  `git diff --check` pass.
- Agentic eval cites trajectory evidence and is separate from deterministic tests.
- An independent reviewer returns a reproducible `PASS`; every accepted finding
  is reproduced, repaired, and retested.
- The pull request says `Closes #N` and reports unrun external steps honestly.
- A person accepts, sends back, rejects, or stops. Participants do not merge or deploy.

## Product contracts

- Market time remains interval-ending fixed AEST; processing time remains UTC.
- Corrections, intervention rows, immutable source provenance, and valid unknown
  pseudo units remain visible.
- App market-wide constraint and source-sign flow summaries have no regional
  allocation or directional interpretation.
- Analytics is the lakehouse read path; writable investigation state belongs in
  native Lakebase and uses trusted identity and parameterised SQL.
- Lakebase history is immutable; current state handles insert, update preimage,
  update postimage, delete, retry, and re-snapshot events.
- ML features are point-in-time safe, splits are chronological, and no fixture
  supports a useful-performance claim, `@prod` change, or serving endpoint.

Prepared fixtures can satisfy local behaviour only. Deployment, synced-table
reconciliation, native Lakebase CDF enablement, live change proof, and serverless
ML execution need separate facilitator evidence.
