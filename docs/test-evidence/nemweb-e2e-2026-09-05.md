## Live preparation and repairs

1. Switching the snapshot pipeline itself to the live sibling failed because its Auto Loader checkpoints retained snapshot file-system paths. No full refresh or checkpoint deletion was used.
2. A new `live_evidence` bundle target and `agentic_energy_workshop_d4_live` schema provided independent tables and checkpoints while reading the existing run-owned Volume's `live/` sibling.
3. The first selective live update correctly failed closed because monthly registration Bronze tables had not been materialised in the new schema. Manual live context run `461147691889245` landed current context and completed full-graph update `69974698-b8a4-4e56-8b74-2fd97b9f898b` with `full_refresh=false`.
4. A queued scheduled cycle then timed out because its queue delay counted against the former 420-second caller timeout. The caller timeout was raised to 1,200 seconds, below the lander job's one-hour safety bound. This allows queued evidence cycles without weakening network, file-count, byte, or ZIP limits.
5. Post-cycle source listings can advance while a queued cycle finishes. The reviewed evidence contract now accepts at most two five-minute intervals of source lead only when Bronze-to-Gold watermarks, expectations, and duplicate checks are healthy. It separately records signed source-to-Gold and non-negative Bronze-to-Gold processing lag.
6. Re-listed immutable archives retain their first Bronze ingestion owner. Evidence resolves ownership from the current manifest and live Bronze provenance rather than assuming the current lander run created duplicate rows.
7. Overlapping scheduled task windows made timestamp-only lander-run resolution ambiguous. The exact `trigger_info.run_id` link now wins, with the limited timestamp window retained only for older API responses.
