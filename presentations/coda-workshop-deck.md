# Agentic Energy: one issue, one reviewed change

## The workshop result

A cross-functional pair turns one `workshop-ready` GitHub issue into an operator
result and an engineering result that a person can accept or reject.

## The shared lifecycle

1. Select one issue.
2. Inspect the issue, governed `nemweb_foundation/`, and named starter.
3. Define measurable requirements.
4. Propose exact files, deterministic tests, eval, review, and stops.
5. Obtain approval from a person who did not draft the plan.
6. Branch, implement, and test.
7. Run an agentic eval separately from tests.
8. Obtain independent adversarial review and repair accepted findings.
9. Prepare a pull request with `Closes #N`.
10. A person accepts, sends back, rejects, or stops.

## Governed choices

- Fixed-AEST interval-ending market time; UTC processing time.
- Corrections and intervention rows remain visible.
- SCADA output is not five-minute availability.
- Market-wide source-sign flow has no regional allocation or inferred direction.
- Analytics reads lakehouse data; Lakebase owns application writes.
- Lakebase CDF history is immutable; current state handles retries and deletes.
- ML features are point-in-time safe and splits are chronological.
- Prepared fixture output is non-live and cannot prove deployment or model value.

## What can reject a change

A failed contract test, future leakage, untrusted identity, interpolated SQL,
retired API, private identifier, unpaused schedule, unsupported live claim, or
independent `REQUEST_CHANGES` result blocks acceptance.

## Close

Report the issue, changed files, exact command results, eval, independent review,
remaining uncertainty, and human decision. Participants do not merge or deploy.
